AWS Database Activity Streams
Decryption, Filtering & Parquet Sinking

A high-performance Go AWS Lambda consumer that ingests encrypted RDS Database Activity Streams, decrypts envelope payloads using AWS KMS, filters noise via a declarative YAML DSL, and writes compressed Apache Parquet directly to analytical S3 buckets.

Key Capabilities

Engineered for Enterprise Compliance

AWS Encryption SDK & KMS

Performs envelope decryption on raw DAS chunks using the official AWS Encryption SDK for Go (Dafny runtime) verified against the RDS Resource ID encryption context.

SQS Partial Batch Retries

Implements ReportBatchItemFailures. Successful messages commit immediately; only failed records are redriven, preventing duplicate writes and retry storms.

Declarative Filter DSL

Drop high-volume heartbeat queries, strip sensitive compliance fields, and target specific database users/queries with composable AST logic (and, or, not).

Compressed Apache Parquet

Serializes retained JSON records directly into Snappy-compressed Parquet with columnar layout ready for Amazon Athena, AWS Glue, Snowflake, and BigQuery analytics.

Multi-Arch Containers

Standardized multi-stage Docker builds supporting both linux/amd64 and linux/arm64 (AWS Graviton) for maximum performance per dollar.

Environment Configuration

Runtime Environment Variables

Variable Default Description
DAS_FILTER_NAME "" Name of the filter profile in filters/ (e.g. default loads filters/default.yaml or .json).
DAS_RDS_RESOURCE_ID "" The RDS Resource ID (e.g. cluster-ABC123XYZ). Required for AWS KMS encryption context matching.
DAS_KMS_REGION_NAME Current Region AWS Region where the KMS Customer Managed Key (CMK) resides.
DAS_OUTPUT_BUCKET Source Bucket Analytical destination S3 bucket for writing processed Parquet files. Defaults to source bucket if unset.

Declarative Rules Engine

YAML Filter DSL Guide

Configure rule profiles in filters/<name>.yaml to drop noise or isolate security-critical queries.

drop (Field Stripping)

List of top-level or dimension field keys to strip from the output Parquet record before storage (useful for redacting non-essential telemetry or PII).

selector (Equality Match)

Evaluates if a specific dimension exactly matches a value (e.g., type: "selector", dimension: "dbUser", value: "rdsadmin").

contains (Substring & Array Match)

Checks whether a string dimension contains a substring, or an array dimension contains an item (e.g. finding heartbeat query text).

and / or / not (Boolean Combinators)

Recursively nests sub-expressions to create fine-grained filtering conditions.

filters/drop-heartbeats.yaml
YAML 
# Drop verbose audit fields
drop:
  - clientApplication
  - serverHost

# Drop internal RDS heartbeat queries
query:
  type: not
  field:
    type: or
    fields:
      - type: selector
        dimension: dbUser
        value: rdsadmin
      - type: contains
        dimension: commandText
        value: "SELECT 1"
      - type: contains
        dimension: commandText
        value: "rds_heartbeat"

Production Operations

Deployment & Packaging

Deploy via CloudFormation

The template in deploy/cloudformation/lambda.yaml provisions the SQS queue, dead-letter queue (DLQ), execution roles, and Lambda event mapping: 

aws cloudformation deploy \
  --template-file deploy/cloudformation/lambda.yaml \
  --stack-name aws-das-processor \
  --capabilities CAPABILITY_IAM \
  --parameter-overrides \
    DasSnsTopicArn=arn:aws:sns:region:acct:das-topic \
    DasSourceBucketArn=arn:aws:s3:::source-das-bucket \
    DasDestinationBucketName=analytics-das-parquet \
    KmsKeyArn=arn:aws:kms:region:acct:key/das-key \
    RdsResourceId=cluster-ABCD1234EFGH \
    LambdaImageUri=123456789012.dkr.ecr.region.amazonaws.com/aws-das-processor:latest

Local Build & Packaging

Use standard Makefile commands to compile, test, and containerize: 

# Build Lambda zip bundle (bin/aws-das-processor.zip)
make lambda-package

# Build multi-architecture container
make docker-build-multiarch

# Run all unit tests with coverage
make test-coverage

# Serve documentation locally on http://localhost:8080
make docs-serve
